AST Security Reviewer

A GitHub Action that flags SQL injection and hardcoded secrets on the exact line of a pull request, with optional fix suggestions from a model that runs on your own machine.

Java 21 / JavaParser / GitHub Actions / Spring Boot / Ollama / JUnit / Docker
Problem
SQL injection and hardcoded secrets slip through code review, and many teams can't send their code to a cloud AI.
How
JavaParser AST visitors walk each file as a syntax tree instead of regex-matching text, so they catch a query built three lines up. Any Java repo can add it as a GitHub Action in about 2 minutes. An optional Spring Boot webhook (verified with constant-time HMAC-SHA256) asks a local Qwen 2.5 Coder model for a fix and re-parses it so only valid Java is posted back.
Result
Ran it on 31 open-source projects (27,552 files) and cut secret false alarms from 156 to 27, 83% fewer, while still catching every real secret in that survey. Published on the GitHub Marketplace, with the SQL rule's weak OWASP Benchmark score reported honestly in the README.

Systems · Networking

HTTP Caching Proxy

A multithreaded, event-driven forward proxy written from scratch in C.

C / pthreads / kqueue / sockets / Python tests
Problem
Every repeat request to the same site went all the way upstream, about 142 ms each time.
How
Non-blocking kqueue event loop with a POSIX worker thread pool, an LRU + TTL response cache behind a mutex, per-client token-bucket rate limiting, a subdomain-aware blacklist and a live JSON /stats endpoint.
Result
12,500+ cached requests/sec from 50 concurrent clients with 0 errors. Cache hits come back in about 1.85 ms. 14 tests pass under AddressSanitizer and ThreadSanitizer.

03
AI infrastructure

LLM Caching Proxy

A drop-in cache for local LLMs, written in C. Point your app at it instead of Ollama and repeat requests come back from memory.

C / pthreads / POSIX sockets / Ollama / Docker / Python tests
Problem
A local LLM re-runs the whole model even for a prompt it has already answered, and one slow client blocks everyone behind it.
How
A thread per client over raw sockets, with a mutex-protected LRU cache in front of Ollama. It speaks the Ollama and OpenAI-style APIs, streaming included, and returns responses byte for byte with an X-Cache: HIT/MISS header. It only caches responses that provably finished, a fix I shipped after a Reddit user found a partial-response bug.
Result
Repeat prompts answered in under 1 ms. 20 concurrent one-second calls went from about 20 s to about 1 s. 1,000 requests from 50 clients finished with 0 errors against a mock LLM server.

AI infrastructure · In progress

Resume Matcher Engine

A resume-to-job matcher that runs its own models on an inference engine I'm writing from scratch in C++ and CUDA.

C++17 / CUDA / all-MiniLM-L6-v2 / GPT-2 / Qdrant (optional)
Problem
Job matching usually means sending your resume to someone else's AI API, and keyword filters miss a match when the wording differs.
How
The engine loads the original all-MiniLM-L6-v2 and GPT-2 weights and runs them on the CPU or an NVIDIA GPU with hand-written kernels, with no PyTorch or BLAS at run time. Each job requirement is matched to the closest resume line by meaning, then scored by a small model trained in the repo.
Status
Runs on my laptop today: drop in a resume and job posts, and it ranks the jobs and shows line by line what the resume covers and what it's missing. The public repo and a live demo are coming once it's ready.
